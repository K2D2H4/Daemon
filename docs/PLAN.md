# Daemon — 설계 계획서 v2

> **An open-source, self-hosted AI companion that you shape — and that reshapes itself around you.**
>
> PC에 상주하는 자기호스팅 AI 동반자. 유저가 초기 페르소나(성격·목소리·말투)를
> 씨앗으로 정하지만, 대화하며 유저를 알아가는 지식 그래프를 스스로 키우고
> (기억), 그 이해를 바탕으로 **성격 자체가 유저에게 맞춰 진화하며**(페르소나
> 진화), 필요할 때 먼저 말을 건다(선제성).

작성일: 2026-08-03 · 개정: 2026-08-03 (v2) · 상태: 설계 확정, M0 대기
라이선스: MIT 예정 · 타겟: 글로벌
문서 정책: **설계 문서는 한글, 공개 문서·코드·커밋·이슈는 영어**

## 0. v2에서 바뀐 것 (v1을 읽었다면 이것만 보면 됨)

Hermes Agent와 OpenClaw의 실제 구현을 확인한 결과 v1의 전제 몇 개가 틀렸다.

| # | v1 | v2 |
|---|---|---|
| 1 | 기억(그래프 + 회상 스코어링)이 차별점 | **차별점 아님.** OpenClaw가 이미 출하했고 회상 공식까지 동일. **이식한다** (§4) |
| 2 | 차별점 = 음성 + 그래프기억 + 성격진화 | **차별점 = §5 페르소나 자기진화 + §6 자율 선제성, 두 개뿐** (§1) |
| 3 | 스택: FastAPI + Celery + pgvector + SSE | **단일 프로세스 + SQLite + 마크다운 + WebSocket.** Celery·Postgres·SSE 삭제 (§3) |
| 4 | 인터페이스: 웹 채팅 → Phase3 폰 연동 | **텔레그램이 1차 인터페이스.** 웹은 "배운 것" 열람용으로 후순위 (§3) |
| 5 | 음성: Phase3에 로컬 실시간(730ms) | **상용 native audio(Gemini Live / OpenAI Realtime).** 로컬 음성 스택 포기 (§6.5) |
| 6 | 프라이버시가 1번 세일즈포인트 | **1번 자리에서 내려옴.** "선택 가능한 완전 오프라인 경로"로 재배치 (§7) |
| 7 | 성공 기준 = 주관적 체감 | **3층 평가.** 골든셋 + 1탭 라벨 + diff 일지 (§8) |
| 8 | 선제성 = "회상/타이밍/빈도" 3줄 | **후보 5유형 → 결정론적 게이트 → LLM 1회.** 침묵이 기본값 (§6) |

## 1. 정의와 차별점

**정의:** 자기호스팅 · 성격이 진화하는 · 먼저 말 거는 AI 음성 동반자.

**이름의 의미 (Daemon):** ① 『황금나침반』의 데몬 = 주인을 닮아가는 외부 영혼
→ 성격 진화. ② 유닉스 daemon = 백그라운드 상주 프로세스 → PC 상주.
*제품명은 **Daemon**, 배포 패키지명은 **`daemon-ai`** (import 패키지는 `daemon`).
`daemon`은 PyPI·npm 모두 선점돼 있고 유닉스 용어와 충돌한다. 실측 확인: `daemon-ai`는
양쪽 레지스트리 모두 비어 있음. `heydaemon`은 양쪽 비어 있고 GitHub에 동명 레포가
0개라 예비로 남겨둔다(음성용 웨이크워드가 필요해지면).*

### 1.1 실제 경쟁 지형 (조사 결과)

| | 하는 것 | 우리와 겹치는 것 | 우리와 다른 것 |
|---|---|---|---|
| **Hermes Agent** (Nous, MIT) | 자기개선 비서. 상주 게이트웨이 + 25개 메신저, SQLite/FTS5, cron 스케줄러, 스킬 자기개선 | 상주 프로세스, 마크다운 기억(`MEMORY.md`/`USER.md`), 메신저 채널 | 정서 동반자 아님. 선제성은 **사람이 짠 cron**. 페르소나 진화 없음. 임베딩·그래프 없음 |
| **OpenClaw** | 로컬 개인비서. OS 데몬(LaunchAgent/systemd), 마크다운+SQLite 5계층 기억, Dreaming 성찰, Standing Intents | **기억 설계 거의 전부** — 회상 = 유사도 × 최신성감쇠(반감기 30일) × 중요도(1–10), provenance 컬럼, 성찰 통합, Obsidian 연동 플러그인 | **`SOUL.md`는 사람이 손으로 씀. Dreaming이 페르소나를 건드리지 않음(문서 명시).** 선제성은 반응형 — 유저가 말 걸어야 예약 기억이 끼어듦 |
| **음성 쪽** (Gemini Live, OpenAI Realtime, Sesame) | native audio 실시간 대화 | 음성 표면 | 영속 기억·성격 진화·자율 선제성 없음. 세션이 끝나면 사라짐 |

### 1.2 그래서 차별점은 두 개다

1. **페르소나 자기진화 (§5)** — 대화에서 배운 대인 방식이 성격에 피드백된다.
   아무도 안 한다. OpenClaw는 페르소나 파일을 사람이 쓰고, Dreaming이
   의도적으로 건드리지 않는다.
2. **자율 선제성 (§6)** — AI가 스스로 판단해 **먼저 밖으로** 말을 건다.
   아무도 안 한다. 양쪽 모두 반응형이다.

**음성은 차별점이 아니다.** 1B 모델이 오픈소스로 풀렸고 프레임워크가 v1.0을 찍었다.
음성은 위 두 개를 전달하는 **매체**이고, 매체 효과가 압도적이라는 게 음성을
핵심으로 두는 이유다. 성격 진화와 먼저 말 걸기는 텍스트로는 절반만 전달된다.

**기억은 토대이지 자랑거리가 아니다.** 문서·README에서 기억을 차별점으로
내세우지 않는다. 내세우면 후발 모방으로 읽힌다.

## 2. "학습/진화"의 정확한 정의

Daemon은 ②③만 한다. ①은 안 한다.

| | 정체 | Daemon |
|---|---|---|
| ① 파라미터 학습 (fine-tune) | 모델 가중치 변경 | ❌ 안 함 |
| ② **기억 축적** | 사실·대화를 저장·구조화·회상 | ✅ §4 |
| ③ **페르소나 진화** | 대인 방식을 학습해 성격에 반영 | ✅ §5 |

"살아있다"는 체감은 ②+③에서 온다. 의식이 자라는 게 아니라 **기억과 성격이 자란다.**

## 3. 아키텍처

```
┌─────────────────────────────────────────────────────────────┐
│  DAEMON  (단일 프로세스, OS 서비스로 상주 / self-hosted)      │
│                                                             │
│  ① 대화 루프      입력 → 회상 → 응답                          │
│  ② 기억          마크다운 원천 + SQLite(메타·인덱스)   ← 이식  │
│  ③ 성찰          주기적 통합 → 엔티티 노트 갱신        ← 이식  │
│  ④ 페르소나 진화  관찰 → 규칙 → 프롬프트 층에 반영     ← 차별점 │
│  ⑤ 선제성        후보 생성 → 게이트 → 발화             ← 차별점 │
│                                                             │
│  LLM 게이트웨이: 작업별 라우팅 (로컬 Ollama / 상용 BYOK)      │
└─────────────────────────────────────────────────────────────┘
        │ send() + 수신 루프 (얇은 채널 추상화)
   ┌────┴─────┬──────────────┐
 텔레그램    로컬 스피커      (후순위) 웹 UI = "배운 것" 열람
 (1차)      (선제 발화)
```

### 3.1 스택

- **런타임**: Python 단일 프로세스. FastAPI(async) + **인프로세스 스케줄러**
  (APScheduler). Celery·Redis 없음 — 유저가 1명이라 분산 워커의 존재 이유가 없다.
- **저장소**: **마크다운 파일이 원천** + **SQLite**(메타데이터·FTS5·벡터 인덱스).
  Postgres/pgvector 안 씀. **벡터 인덱스는 M1b에 포함**(당초 M2 예정에서 앞당김 —
  근거는 §4.3).
- **상주**: macOS LaunchAgent / Linux systemd user unit / Windows 예약작업.
  **선제성의 전제조건** — 터미널이 닫혀 있고 재부팅한 뒤에도 살아 있어야 한다.
- **실시간**: **WebSocket**(음성 API가 WebSocket/WebRTC 기반). SSE는 단방향이라 부적합.
- **채널**: `send(text)` + 수신 루프 두 개로 얇게 감싼다. 텔레그램이 1차,
  로컬 스피커가 두 번째. 과설계가 아니라 Hermes/OpenClaw가 모두 둔 이음새.
- **음성**: 상용 native audio. Gemini Live 먼저, OpenAI Realtime 두 번째.

### 3.2 LLM 라우팅 — 스위치 하나가 아니라 작업별 표

| 작업 | 빈도 | 기본 라우팅 | 근거 |
|---|---|---|---|
| 대화 (텍스트) | 높음 | **유저 선택: 로컬 or 상용** | |
| 대화 (음성) | 높음 | 상용 native audio 고정 | native audio에서는 그 모델이 두뇌이자 목소리다 |
| 회상 Lane1 | 매 턴 | **모델 호출 0회** | 음성 지연 예산이 이걸 강제한다 (§4.3) |
| 회상 Lane2 | 드묾 | 대화와 동일 | 회상 의도가 감지될 때만 |
| 선제성 판단 | 5분 틱, 후보 있을 때만 1회 | **로컬 권장** | 상시 작업이라 비용이 누적 |
| 성찰·엔티티 추출 | 하루 1회 | 유저 선택, 상용 권장 | 품질이 그래프 전체에 파급 |
| 페르소나 규칙 생성 | 주 1회 | 성찰과 동일 | |

**축을 두 개로 나눈다.** 프리셋은 *어디서 도는가*를 답하고, `DAEMON_HOSTED_PROVIDER`가
*누구 모델인가*를 답한다(anthropic / openai / gemini). 프리셋이 상용 대화를
Anthropic으로 하드코딩하고 있었는데, 그러면 §3.2가 말한 provider-agnostic이 설정
표면에서만 참이 된다. 두 축을 곱하면 프리셋이 9개가 되므로 질문을 분리했다.
`CHAT_VOICE`만 예외로 Gemini를 명시한다 — native audio 세션이 그것뿐이고, 음성 세션이
없는 provider를 가리키면 시작 시점이 아니라 첫 음성 턴에 터진다.

**프리셋 3개로 노출한다.** 온보딩에서 7번 고르게 하면 아무도 안 쓴다.

| 프리셋 | 대화 | 성찰 | 선제성 판단 | 음성 |
|---|---|---|---|---|
| **완전 오프라인** | 로컬 | 로컬 | 로컬 | 불가 |
| **균형** (기본값) | 상용 | 상용 | 로컬 | 가능 |
| **품질 우선** | 상용 | 상용 | 상용 | 가능 |

고급 설정에서 개별 덮어쓰기 허용. **"완전 오프라인"이 실재해야 §7의 약속이 참이 된다.**

### 3.2.1 오프라인 프리셋 실측 (2026-08-03, M4 Max)

**끝까지 동작하는 것을 확인했다** — 대화·임베딩·회상 전부 로컬, 마크다운 기록, 회상이
이전 턴의 사실을 정확히 되살림. 아무것도 기기를 떠나지 않았다.

**단 로컬 대화 모델로 추론 모델을 쓰면 안 된다.** 같은 한국어 질문 3개:

| 모델 | p50 | 비고 |
|---|---|---|
| `gemma3:4b` (비추론) | **1.7s** | 한국어가 동반자답다 |
| `qwen3:4b` (추론) | **11.8s** | 어색한 회피체, 사고 토큰 1500~2200개 |

차이는 **아무도 보지 않는 사고 사슬**이다 — Ollama가 별도 필드로 돌려주고 우리는 버린다.
그리고 끌 수 없다: `think: false`는 사고를 멈추는 게 아니라 **분리를 멈춰서** 추론
프로즈가 응답 본문이 된다(11.8s로 빨라지지만 쓸 수 없다). `think: "low"`는 더 느리고,
Qwen3의 `/no_think` 접미사는 Ollama 템플릿을 통과하지 못한다.

그래서 기본값을 `gemma3:4b`로 바꿨다. **이 한 줄이 오프라인 경로를 "기술적으로는
되지만 못 쓸 만큼 느림"에서 "실제로 쓸 수 있음"으로 옮긴다.**

## 4. 기억 — OpenClaw 설계를 이식한다

재설계하지 않는다. 남이 값을 치른 다섯 가지를 그대로 가져온다.

### 4.1 5계층 분리 (핵심)

```
① 지시       AGENTS.md 상당           사람만 씀. 항상 주입
② 큐레이션    memory/core.md          AI가 성찰로 씀. 항상 주입 (예산 제한)
③ 에피소드    memory/log/YYYY-MM-DD.md  AI가 append. 자동주입 안 함, 검색만
             memory/entities/{이름}.md  AI가 갱신. [[링크]]로 연결
④ 예정       SQLite (선제성 후보)      조건 충족 시 발화 (§6)
⑤ 리뷰       memory/reflections/       성찰 산출물, 사람이 검토용
```

**경계가 중요하다**: 항상 주입되는 작은 큐레이션 계층과, 검색만 되는 큰 에피소드
계층을 섞으면 컨텍스트가 터지거나 회상이 무의미해진다.

### 4.2 provenance는 프로즈가 아니라 DB 컬럼에

모델이 산문으로 위조할 수 없는 위치에 둔다.

- `origin` ∈ {owner, agent, untrusted, system}
- `session_kind` ∈ {interactive, voice, proactive, reflection}
- `modality` ∈ {text, voice} — **음성 관찰과 텍스트 관찰의 품질이 다르므로 기록한다**
- `created_at`, `importance`(1–10), `supersession_key`

**위생 규칙 2개**: ① 선제성·성찰 세션은 영구 기억을 만들지 못한다(자기 발화가
기억이 되어 증폭되는 루프 차단) ② 회상된 내용은 마킹해서 재추출을 막는다.

**미러는 실제로 재생성 가능해야 한다.** "sqlite를 지워도 마크다운으로 되살아난다"는
말로만 두면 참이 아니다 — 미러 쓰기가 실패한 턴은 모델의 컨텍스트에서 영구히
사라지고 감지 수단도 없다. 부팅 시 마크다운과 미러의 레코드 수를 비교해 부족한 꼬리를
채운다(로그는 append-only라 부족분은 항상 꼬리다). 단 **provenance는 복구할 수 없다** —
마크다운이 의도적으로 안 갖고 있기 때문이다. 재생성된 행은 `reindexed = 1`로 표시해서
성찰이 추정값과 관측값을 구분할 수 있게 한다.

**원천은 미러보다 최소한 같은 수준으로 durable해야 한다.** sqlite가 WAL +
`synchronous=FULL`로 커밋마다 fsync하는데 마크다운을 fsync하지 않으면, "마크다운 먼저"는
호출 순서일 뿐 영속 순서는 반대가 된다 — 정전 시 sqlite에는 있고 원천에는 없는 행이
남는다. append마다 fsync한다.

### 4.3 회상 2레인

- **Lane1 (모델 호출 0회, 매 턴)**: 큐레이션 계층 부트스트랩 주입 +
  `점수 = 하이브리드 유사도 × 지수 최신성감쇠(반감기 30일) × 중요도(1–10)`
  + 트리거 구절 매칭.
  **음성 모드에서 회상이 800ms 걸리면 못 쓴다. 이 레인이 LLM 호출 0회여야 하는 건
  취향이 아니라 지연 예산의 강제다.**
- **Lane2 (에스컬레이션)**: 회상 의도가 감지되고 Lane1이 약할 때만 블로킹 서브에이전트.

**한국어에서 FTS5만으로는 부족하다 (실측).** SQLite `unicode61` 토크나이저는 한국어
형태소를 모른다 — `김치찌개`는 잡히고 `김치*`(접두)도 잡히지만 `김치찌`는 안 잡히고,
조사가 붙은 `어제는`과 `어제`는 별개 토큰이다. 즉 영어라면 Hermes처럼 FTS5만으로
굴러가지만 한국어는 안 된다. **그래서 벡터 인덱스를 M2에서 M1b로 앞당겼다** — 회상이
안 되면 M1b 게이트("어제 말한 걸 오늘 정확히 인용")를 한국어로 통과할 수 없다.
(형태소 분석기를 붙이는 대안은 의존성이 무거워지고 self-host 마찰이 커져서 보류.)

**M1b 구현 주의**: FTS5는 바인딩된 값도 쿼리 *문법*으로 파싱한다. 유저 발화를 그대로
`MATCH ?`에 넣으면 `"` `*` `NEAR` `:` 때문에 터지거나 의도치 않은 컬럼 필터가 된다.
토큰을 추출해 인용부호로 감싸야 한다.

### 4.3.1 실측 (2026-08-03, M4 Max, bge-m3)

**정정: "임베더 호출은 로컬이라 수 ms"라고 적었던 것은 40배 틀렸다.**

| 구간 | p50 |
|---|---|
| 임베더 왕복 1건 | **117 ms** |
| FTS5 레인 + 벡터 레인 + 스코어링 | **약 1 ms** |
| `search(limit=6)` 전체 | **121 ms** |

원인은 추론이 아니라 고정 오버헤드다 — 배치 1건 117ms, 4건 149ms이므로 **고정비가
약 105ms, 텍스트당 한계비용은 11ms**다(배치 64에서 12.4ms/건). 따라서:

- **더 작은 모델로 줄일 수 없다.** `paraphrase-multilingual`(562MB, 768차원)은
  124ms로 **더 느리고** 골든셋도 93.3% → 83.3%로 떨어진다. bge-m3를 유지한다.
- **배치가 크게 이득이라 `backfill`은 반드시 배치로 돌린다**(건당 117ms → 12ms).
- **음성에서의 대응은 아키텍처다**: 상용 realtime이 **부분 전사(partial transcript)를
  주므로, 유저가 아직 말하는 동안 부분 전사를 임베딩해두면** 발화가 끝나는 시점에
  임베딩이 준비돼 있다. 추가 지연 0. LLM 워밍업과 같은 수법이고, **음성 마일스톤의
  요구사항으로 못박는다.**
- 텍스트 모드에서 117ms는 무의미하다 — 어차피 모델 응답을 초 단위로 기다린다.

**측정치의 조건**: 93.3%는 임베딩이 **전부** 색인된 상태의 수치다. 감사에서 드러난
대로 프로덕션 backfill은 한 번만·500건만·오래된 것부터 돌고 있었고(골든셋은
`limit=10_000`을 썼다), 1만 건 히스토리에서는 대부분이 벡터 없이 남아 실제로는
키워드 전용 50%에 가까웠을 것이다. 소진 루프 + 최신 우선으로 고쳤다. **회상 품질을
보고할 때는 색인 완료 여부를 함께 봐야 한다** — 그래서 `/health`가 벡터 개수를
노출한다.

**그리고 스케일 리스크는 벡터가 아니라 FTS5다.** 10k 메시지에서 벡터 레인 0.22ms 대
FTS5 레인 1.9ms, 50k에서 1.29ms 대 9.1ms — 흔한 토큰 6개를 OR로 묶는 쿼리가 더 비싸다.
둘 다 음성 예산 안이지만, 걱정할 대상의 방향이 직관과 반대다.

### 4.4 supersession

모순을 누적하지 않는다. 같은 `supersession_key`의 새 사실이 오면 기존 항목을
retire하고 대체한다. append-only로 쌓으면 "여자친구 있음/없음"이 공존하게 된다.

### 4.5 옵시디언

**파일 포맷 호환만 가져간다. 의존성으로 삼지 않는다.**
`[[링크]]`는 Logseq·Foam 등도 읽는 사실상 표준이라 공짜다. 그래프 뷰는
데모·README 소재로 강력하다. 하지만 ① 옵시디언은 오픈소스가 아니고 상업 사용은
유료다 ② OpenClaw에 이미 `memory-wiki` 플러그인이 있다 ③ §5의 "배운 것 열람"은
자체 UI가 필요하다(규칙 삭제·되돌리기는 파일 편집으로 못 시킨다).

## 5. 페르소나 진화 — 차별점 ①

### 5.1 파일 소유권 3분할 = 앵커의 구현

```
persona/seed.md      사람만 씀. AI는 읽기만.        ← 이게 앵커
persona/learned.md   AI만 씀. 사람은 읽기 + 삭제요청만.
memory/**            AI만 씀.
```

프롬프트 조립 시 `seed.md` + `learned.md`를 합친다. **AI가 구조적으로 못 건드리는
파일이 존재하는 것 자체가 "성격 붕괴" 방지 장치다.** 별도 기능이 필요 없다.

이 분할은 쓰기 충돌도 동시에 해결한다 — 사람이 옵시디언에서 편집하는 파일과
AI가 재작성하는 파일이 겹치지 않는다. (겹치는 지점에는 콘텐츠 해시 낙관적 동시성
+ atomic rename을 쓴다.)

### 5.2 진화 루프

```
대화 → 성찰이 "이 사람 다루는 법"을 관찰로 추출
       ("아침엔 짧게 거는 게 반응 좋았음", "조언보다 들어주기를 원함")
   → 관찰이 N개 쌓이면 규칙 후보 생성 → learned.md에 반영
   → 다음 대화의 성격이 미세하게 유저에게 맞춰짐
```

구현은 **프롬프트/설정 층의 진화**다. fine-tune이 아니다.

### 5.3 변화율 제한

- `learned.md`의 활성 규칙 **개수 상한** (초기값 20)
- **주기당 추가 상한** (초기값 주 3개)
- 규칙마다 SQLite에 `created_at`, 근거 세션, `status`(active/retired), 승계 키.
  **산문 주석에 넣으면 모델이 위조하거나 뭉개서 되돌리기와 변화율 계산이 불가능해진다.**

### 5.4 앵커에 박는 불변 항목 (품질 항목)

`seed.md`에 다음을 씨앗 핵심으로 넣는다: **"나는 유저에게 동의만 하지 않는다.
필요하면 반대한다."** AI가 이 파일을 못 건드리므로 진화가 이걸 지울 수 없다.

이건 윤리 장치가 아니라 **품질 장치**다. 동의만 하는 캐릭터는 재미없고 신뢰가
안 간다(Her의 사만다도 반대하고 화낸다). 부수적으로 v1이 지적한 "과적응
(에코챔버)" 위험의 구조적 답이 된다.

### 5.5 투명성

유저가 "네가 나에 대해 뭘 배웠는지"를 열어볼 수 있어야 한다 — 규칙 목록, 각
규칙의 생성 시각과 근거, 주간 diff. 신뢰의 근거이자 이 프로젝트의 데모 포인트다.

## 6. 선제성 — 차별점 ②

캐릭터챗과 Daemon을 가르는 한 줄: **AI가 먼저 말을 건다.**

### 6.1 3단 구조

```
[1단] 후보 생성기 — 결정론적, 모델 호출 0회, 5분마다 틱
  유형A 미완 맥락   만기된 open loop ("내일 발표" → 다음날 저녁)
  유형B 정서 후속   최근 대화의 감정 신호 + 경과시간
  유형C 침묵        N시간 무대화 + 유휴 아님
  유형D 패턴 시각   평소 대화하던 시간대인데 오늘 없음
  유형E 연상        회상 인덱스에서 최근 맥락과 강하게 연결된 오래된 기억

[2단] 게이트 — 결정론적
  유휴시간(ioreg HIDIdleTime) · 포그라운드 앱 · 오디오 점유(통화 중)
  · 조용시간(유저 설정) · 쿨다운 · 유형별 일일 예산

[3단] LLM 1회 — 게이트를 통과한 후보에만
  "지금 이 이유로 말 걸 가치가 있나? 있으면 한 마디로"
```

**유형E는 의도된 침묵으로 출하됐다 (2026-08-04).** 생성기 4개가 돌고 E는 이유를 적어둔
빈 자리다. 진입점이 `MemoryRecall.search` 하나뿐이었고 그게 두 번 틀린다: ① 점수에
최신성 감쇠(30일 반감기)를 곱하므로 3개월 된 기억은 0.125배로 도착한다 — 감쇠가 묻으려는
것이 정확히 유형E가 원하는 것이다 ② 히트마다 `Store.mark_recalled`를 부른다. 아무에게도
보여주지 않은 행에 `recalled = 1`을 찍는 5분 백그라운드 틱이고, §4.2 위생 규칙 2가 그
행을 성찰에서 **영구히** 제외한다 — 생성기가 성찰 패스를 조용히 굶히는 셈이다. 그래서
회상에 `MemoryRecall.associate()`를 뒀다: 감쇠 없음, 최소 연령, 표시 없음. 생성기를
붙이는 일만 남았고, 잘못 붙인 생성기보다 없는 생성기가 낫다는 판단이 그 사이를 채운다.

### 6.2 왜 이 구조인가

- **타이밍을 LLM에 맡기면 안 된다.** LLM은 유저가 지금 회의 중인지 모른다.
  결정론적 신호로 먼저 차단하고, LLM에는 "말할 내용이 있는가"만 묻는다.
- **비대칭 기본값 — 침묵이 기본이다.** LLM에 "말 걸까?"를 열린 질문으로 물으면
  거의 항상 "그렇다"고 답한다. 판단을 마지막 1회로 좁히고, 후보가 없으면 LLM을
  부르지도 않는다.
- **유형별 예산을 따로 둔다.** 계산하기 쉬운 유형A(리마인더)가 예산을 다 먹으면
  "유능한 비서"가 되고 동반자가 아니게 된다. Her의 감각은 오히려 용건 없는
  유형B·E에서 온다. 초기값: 전체 하루 3회, 그중 유형A는 1회까지.
- 유형A는 OpenClaw의 Standing Intents를 **밖으로 나가는 방향으로 뒤집은 것**이다.
  구조(상태기계 pending/armed/fired, 쿨다운·발화예산·만료)를 이식하고 트리거를
  유저 발화 대신 시간·조건으로, 결과를 숨은 컨텍스트 대신 발신으로 바꾼다.

### 6.2.1 판단 프롬프트 실측 (2026-08-04, gemma3:4b)

§6.2의 *"LLM에 '말 걸까?'를 열린 질문으로 물으면 거의 항상 '그렇다'고 답한다"*를 실제로
시험했다. **질문을 좁히는 것만으로는 부족하다.**

| 프롬프트 | 거절 |
|---|---|
| 거절이 허용되고 정당하다고 명시 ("빈 문자열은 실패가 아니다") | **15회 중 0회** |
| 침묵을 기본값으로 두고 발화를 예외로, 조건 2개 | **15회 중 3회** — 전부 내용 없는 이유에 |

첫 프롬프트는 `특별한 일은 없다.`라는 이유에도 `별일 없어.`로 답했고, 씨앗의 반말에서
`발표 결과는 어땠나요?`·`그렇습니까`로 이탈했다. 침묵을 기본값으로 바꾸니 이름 붙은
사건이나 감정이 있는 이유는 씨앗 말투의 쓸 만한 문장(`발표 결과는 어땠어?`)을 냈고 내용
없는 이유는 거절했다. **§6.2의 판단은 질문을 좁힌 뒤에도 유효하다** — 좁히지 않으면 3단이
아니라 2단이 되고, 게이트가 통과시킨 모든 후보가 곧 발화가 된다.

남은 구멍도 적어둔다. `silence`와 `pattern_time`의 이유에는 경과 시간과 빈도밖에 없어서
4B 모델이 그 자리를 빈말로 채운다(`또 왔네.`, `전혀 변한 게 없어.`). 이유만 읽는 모델이
"이 유형은 애초에 물을 것이 없다"를 알 수는 없고 알아야 할 것도 아니다 — **"이 유형은 덜
말한다"는 예산이고, 예산은 2단 게이트와 라벨 기반 튜닝의 몫이다.**

### 6.3 전달 경로 — presence로 라우팅

```
"말할 이유가 있다"
      │
 ┌────┴────┐
PC 앞에 있다        자리에 없다 / 잠금
(idle < N분)              │
      │                텔레그램
로컬 스피커            (텍스트 또는 음성메모)
(기기를 아무것도 떠나지 않음)
```

**동시 전달**: 스피커로 말하면서 같은 내용을 텔레그램에도 남긴다. 스피커가 말을
걸었는데 대답을 키보드로 치는 어색함을 완화하고, 못 들었을 때의 유실을 막는다.

측정 확인 완료 (M4 Max): `ioreg` HIDIdleTime 존재, osascript 포그라운드 앱 조회 응답,
`/usr/bin/say` 한국어 음성 존재, ffmpeg 존재(텔레그램 음성메모 OGG/Opus).
**단 "작동 확인"이 "쓸 수 있다"는 아니었다** — 셋 중 둘은 단위가 틀렸거나 아예 죽어
있었고 하나는 게이트가 비교하는 어휘와 달랐다. §6.3.1.

**presence는 불리언이 아니라 3값이다.** 답할 수 없는 프로브는 `None`을 주고, `None`은
"있다"도 "없다"도 아니다 — 알 수 없는 presence는 스피커로 가지 않는다. 비싼 실패 쪽을
거부하는 것이 §6.4의 비대칭이고, 그게 이 필드가 `bool`이 아닌 이유다.

### 6.3.1 presence 프로브 실측 (2026-08-04, M4 Max / Darwin 25.5.0)

읽어서가 아니라 돌려서 나온 정정 세 개다. 전부 §6.3이 "작동 확인"으로 적어둔 프로브다.

1. **`HIDIdleTime`은 나노초다.** 2.0초 sleep을 사이에 두고 두 번 샘플링해 1e9로 나누니
   2.017 / 2.024 / 2.032초 — 벽시계와 소수점 세 자리까지 맞으므로 단위는 추측이 아니다.
   반대로 틀리면 모든 읽기가 idle ≈ 0이 되고, 그건 "키보드 앞에 있다"이고, 그건 스피커다.
2. **`ioreg` 기반 오디오 프로브는 Apple Silicon에서 전부 죽었다.** `afplay`가 확실히
   재생 중인 상태에서 `IOAudioEngine`·`AppleHDAEngineOutput`·`IOUserAudioDevice`가 모두
   아무것도 반환하지 않았다 — 이 IORegistry에 그 클래스들이 없다. 대신 CoreAudio의
   `kAudioDevicePropertyDeviceIsRunningSomewhere`를 ctypes로 읽으면 되고, **입력**
   장치에서도 된다. "통화 중"의 실체는 마이크 점유 쪽이므로 그게 오히려 본론이다.
3. **`name of ... application process`는 앱 이름이 아니라 실행 파일 이름을 준다.** 프로브
   두 개를 같은 최전면 창에 대고 경쟁시키니 드러났다: `lsappinfo`는 `Warp`, `osascript`는
   `stable` — Warp의 바이너리가 `/Applications/Warp.app/Contents/MacOS/stable`이다.
   게이트는 이 필드를 **사람이** 설정에 적은 앱 이름과 비교하므로, 어휘가 두 개면 어느
   프로브가 답했는지에 따라 규칙이 켜지거나 꺼진다 — 조용히 고장 나기 전까지만 작동하는
   포커스 규칙이다. `displayed name`이 고친다. 그리고 `lsappinfo`는 7.7ms
   (`osascript`는 233ms)에 TCC 권한도 필요 없어서 이제 그쪽이 1차고 `osascript`가 뒤에 선다.

**미해결이고, 미해결로 두는 것**: LaunchAgent 아래에서 `osascript`가 TCC 동의 대화상자
뒤에서 멈추는지. 확인하려면 동의를 눌러 새 권한을 써야 하고, 그건 이 기계의 보안 설정을
바꾸는 일이다. **더 이상 아무것도 막지 않는다** — `lsappinfo`가 권한 없이 이 필드를
채우고, 세 결과(거부·지연·정상)가 모두 처리돼 있다.

### 6.4 실패 비용의 비대칭

텍스트 알림은 무시하면 되지만 **회의 중 스피커에서 목소리가 나오면 사고다.**
그래서 §6.1의 2단 게이트는 음성 발화의 **선행 의존성**이다. 게이트 없이 음성을
켜지 않는다.

**그리고 이 비대칭이 게이트의 기본값을 한 번 뒤집었다.** `audio_busy = True`는 처음
발화 자체를 막았다 — 장치를 잡고 있으면 통화 중이고 기다리는 건 공짜라는 판단이었다.
돌려보니 전제가 틀렸다. 프로브는 `kAudioDevicePropertyDeviceIsRunningSomewhere`이고
알림 소리·자동재생 영상·시스템 전역 오디오 EQ에도 참이다 — 마지막 것이 개발 기계에
깔려 있었고, 게이트가 하루 종일 전부 침묵시켰다. 음악을 켜두는 사람은 텍스트조차 못
받는다는 뜻이고 그건 §6.1이 피하려는 "죽은봇" 쪽 실패다. 어느 채널이 안전한지는 이
절이 이미 말하고 있다 — **오디오 점유는 이제 발화가 아니라 스피커를 잃는다.**
포그라운드 앱과 똑같이 라우팅만 바꾼다.

### 6.5 음성

- **상용 native audio를 쓴다.** Gemini Live 먼저(입력 단가가 32배 저렴, 한국어 양호),
  OpenAI Realtime을 같은 추상화 뒤에 두 번째로. **둘을 지원하는 것이 외부 API
  종속 리스크의 유일한 완화책이다.**
- **음성 사용 여부는 유저가 선택한다.** 텍스트 모드만으로도 완결된 제품이어야 한다.
- **로컬 음성 스택은 포기한다.** 근거: ① STT→LLM→TTS 파이프라인은 구조적으로
  파라언어(톤·억양·속도·멈춤)를 버린다 — 청자는 400ms 안에 로봇임을 감지한다
  ② 오픈웨이트 native audio(Qwen3-Omni, Apache 2.0)는 존재하지만 Apple Silicon
  MLX 변환본이 **텍스트 전용**이라 Mac에서 음성 생성 경로가 없다
  ③ 후속 Qwen3.5-Omni는 비공개로 전환됐다.
- 비용: 하루 30분 대화 기준 Gemini Live 약 $20/월, OpenAI mini 약 $14/월,
  base 약 $45/월. **BYOK이므로 유저가 낸다.** 텍스트 모드는 무료(로컬)라 계단이 생긴다.
- **선제 발화에 세션을 상시 열지 않는다.** 말하기로 판단한 순간 세션을 열고
  말하고, 유저가 응답할 때만 입력 스트림을 연다. 선제 발화는 지연이 무관하다.
- 상용 realtime API는 **입출력 전사(transcript)를 제공한다.** 따라서 §4 기억과
  §5 페르소나 진화가 음성 모드에서도 온전히 작동한다. 단 Gemini는 partial/final
  구분 없이 **델타로 흘려준다** — 턴 경계에서 누적해 한 번에 기록해야 한다. 델타를
  그대로 기록하면 음절 하나가 발화로 남는다.
- **verbatim TTS 경로가 Live API에 없다.** `realtimeInput.text`는 프롬프트라서 모델이
  그 텍스트에 *답한다*(읽어주지 않는다). 그래서 "이 문장을 그대로 말해"는 로컬
  스피커의 일이고, 그게 §6.3의 PC 앞 선제 발화 경로와 정확히 같다 — 기기를 떠나지도
  않는다. macOS `say`로 한국어 발화가 실제로 되는 것을 확인했다(ko_KR 음성 9개).
- **끼어들기에 클라이언트측 취소 메시지가 없다.** 서버측 VAD에서는 유저의 오디오가
  생성을 멈추고 `serverContent.interrupted`로 통보된다. 그러므로 우리 쪽 대응은
  ① 버려진 턴의 오디오를 더 넘기지 않기 ② 스피커 큐를 비우기 **두 개 다** 필요하다.
  하나만 하면 계속 떠든다.
- 오디오 포맷이 방향마다 다르다 — **입력 16kHz, 출력 24kHz.** 한 필드로 묶으면
  출력을 16k로 재생하는 피치 버그가 난다.

### 6.5.1 M0 스파이크 실측 (2026-08-03, 실제 키, `gemini-3.1-flash-live-preview`)

```
setup (핸드셰이크 + setupComplete)   0.56 s
time to first audio                  740 ms
전체 턴                              2.52 s, PCM 309,122 bytes
전사   [assistant] final=True '오늘 하루도 수고 많았어요. 지금은 편안하게 쉬어주세요. 힘내세요!'
잘못된 키                            close 1007 "API key not valid" → permanent 분류 정상
```

확정된 것:
- **모델 id는 `gemini-3.1-flash-live-preview`이고 `models/` 접두사가 필수다.** 빼면
  `1008 ... is not found for API version v1beta`.
- `x-goog-api-key` 헤더 인증이 동작한다(쿼리 파라미터 불필요 — 키가 URL에 안 들어간다).
- setup 형태는 SDK 쪽이 맞다. `responseModalities`를 setup 최상위로 올리면 `1007 Unknown name`.
- **`clientContent` + `turnComplete: false` 는 응답 0·전사 0** — 즉 응답을 트리거하지 않고
  컨텍스트만 심는다. 이게 회상을 음성 턴에 넣는 유일한 경로다(§4.3.1). `realtimeInput.text`는
  프롬프트라서 그걸로 넣으면 데몬이 묻지도 않은 옛 기억을 낭독한다.
- 한국어 전사 델타 누적이 정상이다.

**그리고 §6.5의 지연 논거를 일부 약화시키는 숫자가 나왔다.** 조사 단계에서 unified S2S는
200~300ms, 파이프라인은 튜닝 후 0.7~1.1s로 봤다. 상용 native audio를 고른 이유 중 하나가
지연이었는데 **실측 740ms는 파이프라인 구간의 하단**이다. 즉 지연만으로는 상용을 정당화하기
어렵고, **§6.5가 서는 근거는 파라언어(톤·억양·멈춤)의 왕복**이다 — 그건 파이프라인이
구조적으로 못 하는 것이고 여전히 유효하다. 논거를 정확히 그쪽에 둔다.

**두 개는 추론이 실측에 반박됐다.** ① 잘못된 키는 1008이 아니라 **1007**이다. ② `1008`은
영구가 아니다 — `The operation was aborted.`는 유휴 세션 abort이고 재연결하면 된다. 코드가
아니라 이유 문자열로 구별해야 한다.

**결함 하나는 정상 소비 방식에서만 드러났다.** `receive()`가 턴 경계에서 종료되지 않아,
`async for`를 끝까지 도는 호출자는 최종 전사(2.6s)를 받고 나서 영원히 대기하고 서버가
세션을 끊는다. 5개에서 `break`하면 통과한다 — 단위 테스트로는 절대 안 나오는 종류다.

## 7. 프라이버시 — 재작성됨

v1의 "내 데이터가 내 기기를 안 떠난다"를 1번 세일즈포인트로 쓸 수 없다.
음성 모드는 오디오를 제공자로 보내고, 텔레그램은 대화를 텔레그램 서버로 보낸다.
**정직한 문구는 이것이다:**

> 기억과 페르소나는 당신의 기기에만 있다. 파일이 원천이고, 언제든 열어보고
> 지울 수 있다.
> 음성 모드를 켜면 오디오는 **당신이 고른 제공자**로 간다(BYOK). 켜지 않으면 안 간다.
> **텍스트 모드 + 로컬 모델("완전 오프라인" 프리셋)은 아무것도 기기를 떠나지 않는다.**
> PC 앞에 있을 때의 선제 발화는 로컬 스피커로 나가므로 어떤 경로도 타지 않는다.

- 기억·페르소나·관찰·라벨 전부 로컬 파일 + 로컬 SQLite. 클라우드 강제 없음.
- 상용은 전부 BYOK. 하드 예산 차단기 + 레이트리밋.
- 채널 선택지를 하나 더 준다(로컬 알림, 또는 self-host 가능한 푸시). 텔레그램
  강제가 되면 위 문구가 약해진다.

## 8. 로드맵과 검증

### 8.1 시계가 두 개다 (일정의 핵심)

작업일(person-day)은 손을 빨리 움직이면 줄지만 **벽시계 시간은 안 줄어든다.**
차별점 두 개가 하필 벽시계 쪽이다.

| 시계 | 언제 시작 | 소급 | 왜 필요 |
|---|---|---|---|
| **로그 시계** | 대화가 파일에 쌓이기 시작한 날 | **가능** — 성찰을 켤 때 이전 로그를 배치로 훑으면 된다 | 페르소나 진화 판정에 관찰 2주 누적 필요 |
| **라벨 시계** | 후보 생성기가 실제로 도는 날 | **불가** — 실시간 판단과 그때의 반응이 라벨이다 | 선제성 정밀도에 라벨 수십 개 필요(3~4주) |

**따라서 M1a를 가장 먼저·가장 작게 두어 로그 시계를 최우선 점화한다.**
완벽한 M1보다 거친 M1이 전체 일정에서 이긴다.

**그리고 라벨 시계는 한 단어 때문에 안 켜져 있었다 (2026-08-04에 발견).** 인라인 👍/👎
버튼은 M1a부터 붙어 있었는데 텔레그램 `getUpdates`의 `allowed_updates`가 `["message"]`
였다 — **서버측 필터라서 버튼을 한 번 누르는 것이 애초에 배달되지 않는다.** 그러면 라벨
수는 0이고, 0은 "주인이 라벨을 안 누른다"로 읽히고, 어디에도 이유가 남지 않는다. 압축
불가능한 시계 하나가 통째로 멈춰 있는데 로그는 건강해 보이는 상태였고, §8.3의 두 번째
층 전체가 여기에 달려 있다.

후순위(v1의 Phase 4~5): 멀티모달 인지, 스킬 진화(DSPy/GEPA류),
커뮤니티·페르소나 공유. **어느 것도 M4 전에 들어오지 않는다.**

### 8.2.1 M2 전반부 실측 (2026-08-04, gemma3:4b)

**들어간 것.** 하루치 대화를 읽어 세 가지를 쓴다 — 큐레이션 사실은
`data/memory/core.md`(+ `memory_entries` 미러), 엔티티 노트는
`data/memory/entities/`(+ `entities`·`entity_links`), 관찰은 append-only
`observations`. 사람이 검토하는 산출물은 `data/memory/reflections/`에 남고, 그 파일이
동시에 멱등성 마커다(`daemon/memory/schema.sql`이 frozen이고, "이 날은 성찰했다"는
상태는 어차피 계약의 마크다운 쪽에 속한다). 04:00 **로컬 시간** 잡(`daemon/app.py`의
`REFLECT_HOUR`)과 손으로 돌리는 `daemon reflect`가 `build_reflection` 이음새를 공유한다.
`daemon doctor`는 큐레이션 사실 수·엔티티 수·관찰 수·미성찰 백로그·그래프 상위를
보고하고, `daemon reindex`는 마크다운 3계층(로그·큐레이션·엔티티) 전부를 미러에
복원한다 — 메시지만 복원하면 성찰이 만든 사실과 노트를 전부 잃는다.

**전반부에 안 들어갔던 것, 그리고 그 뒤.** 회상이 큐레이션 계층을 주입하지 않는 상태로
전반부가 끝났다 — §4.3 Lane1의 "큐레이션 계층 부트스트랩 주입" 부분이고, 성찰이 쓰는 것과
대화가 읽는 것이 이어지지 않은 동안은 게이트를 통과했다고 말할 수 없었다. **같은 날 해소됐고
M2는 ✅다**: `search()`가 검색 히트 뒤에 항상 주입되는 큐레이션 계층을 붙이고, 임베더 호출은
0회다(활성 50항목에서 0.07ms — 비교 대상인 임베더 왕복이 117ms).

**실제로 돌려서 나온 결함 2개.** 둘 다 단위 테스트가 못 잡았고, 둘 다 손으로 쓴 모델
응답으로는 재현되지 않는 종류다.

1. **엔티티 노트가 "성찰을 돌린 날"로 찍혔다** — 노트가 다루는 날이 아니라. 몇 달치
   히스토리를 처음 따라잡으면 모든 섹션이 오늘 날짜가 되고, 히스토리로 읽히라고 만든
   파일이 히스토리가 아니게 된다. 이제 성찰이 읽은 날을 노트에 넘긴다.
2. **같은 supersession 키를 가진 사실 2개가 결과를 조용히 뒤집었다.** 모델이 이사의
   양쪽을 모두 `location`으로 키잉했다 — "이주 위치: 연희동"(importance 8)과 "이전
   주소: 망원동"(importance 3). 순서대로 적용되니 두 번째가 첫 번째를 retire했고,
   `data/memory/core.md`에는 importance 3짜리가 남고 산출물 파일은 importance 8짜리를
   주장했다. §4.4가 모순을 막으려고 둔 장치가 그 자체로 모순을 만든 셈이다. 이제 쓰기
   전에 해소하고(중요한 쪽을 남긴다) 충돌을 보고한다.

**품질 관찰: 4B 로컬 모델은 이 작업에서 불안정하다.** 같은 6메시지 한국어 픽스처에서
한 번은 사실 1개 / 엔티티 1개 / 관찰 0개, 다른 한 번은 2개 / 2개 / 1개가 나왔다.
무엇이 기억할 가치가 있는지에 대한 판단 자체가 흔들린다는 뜻이다. §3.2가 성찰을
"품질이 그래프 전체에 파급"된다며 상용 권장으로 둔 이유가 여기서 확인된다 — 오프라인
프리셋에서도 돌아가긴 하지만, **성찰은 상용 모델을 가리켜서 얻는 이득이 가장 큰
작업이다.**

### 8.2.2 M3 실측 (2026-08-04)

**들어간 것.** §6.1의 3단이 전부 이어졌다 — 생성기 4개(`daemon/proactivity/candidates.py`),
결정론적 게이트(`daemon/proactivity/gate.py`), presence 프로브
(`daemon/proactivity/presence.py`), 모델 호출 1회(`daemon/proactivity/judge.py`,
`Task.PROACTIVE_JUDGE`), 전달과 기록(`daemon/proactivity/delivery.py`), 로컬 스피커,
그리고 이것들을 묶는 5분 틱(`daemon/proactivity/tick.py`). `daemon proactive`는 한
라운드를 돌려 읽은 값·만기된 후보·어떤 규칙이 허용했거나 막았는지를 출력하고 모델은
부르지 않는다(dry가 기본값이다). `--speak`를 붙이면 실제로 판단하고 전달한다. 5분 잡은
`proactive_enabled`가 켜졌을 때만 스케줄러에 등록된다 — 5분마다 깨어나 말하지 않기로
결정하는 잡은 싸지만 공짜가 아니고, 잡이 아예 없는 것이 "꺼짐"의 더 분명한 표현이다.

**스위치는 둘이고 둘 다 따로 꺼져 있다.** `DAEMON_PROACTIVE_ENABLED`와
`DAEMON_PROACTIVE_SPEAKER_ENABLED`. 실패 비용이 비교 대상이 아니기 때문이다(§6.4):
무시하면 되는 텔레그램 알림과 회의 중 스피커가 스위치 하나를 공유할 수는 없다.
**쿨다운도 둘이다** — `proactive_candidates.cooldown_secs`는 "이 이유를 다시 꺼내지
않는다"(후보별, 기본 1일)이고 `DAEMON_PROACTIVE_COOLDOWN_MINUTES`는 발화 사이의 전역
간격(기본 90분)이다. 후자를 전자에 복사하면 서로 다른 후보 5개가 5분 안에 각자 자기
쿨다운을 지키며 전부 나간다.

**`daemon doctor`가 라벨을 보고한다** — 발화 수, 👍/👎, 미라벨, 답장, 그리고 정밀도.
§8.1의 라벨 시계는 압축되지 않으므로 몇 주가 보여야 하고, 보이게 하는 것이 이 줄이다.
라벨이 하나도 없으면 "정밀도 미지"라고 그대로 적는다. 그리고 **`data/persona/seed.md`가
비었거나 없으면 blocker로 보고한다**: 씨앗 없이 판단기는 모든 후보를 거절하므로(§5 —
일반 비서 말투는 이 제품이 가져서는 안 되는 단 하나다) 선제성이 켜진 채 한 마디도 하지
않는 상태가 되고, 그게 이 프로젝트의 전형적 실패인 조용한 열화다.

**한 단어짜리 결함이 압축 불가능한 시계 하나를 멈춰 있게 했다** — §8.1.

**안 들어간 것.** 유형E(§6.1)와 튜닝. 튜닝은 라벨이 쌓이기 전에 할 수 있는 일이 아니고,
그래서 M3의 게이트는 남은 코드가 아니라 남은 시간에 걸려 있다.

~~MCP 도구 연결~~은 **M1c로 앞당겼다 (§10).** 이 줄이 원래 "M4 전에 안 들어온다"고
못박았으므로, 뒤집은 근거를 남긴다: ① "PC에 상주하는 동반자"라면서 PC를 만질 수
없는 것은 후순위 기능의 부재가 아니라 §1 정의의 미달이다. ② 도구 호출은
provider 계약(`daemon/llm/base.py`)을 건드리므로 나중에 끼울수록 비싸진다 — 4개 제공자를
다시 열어야 한다. ③ §10.2의 게이트는 M3 선제성보다 **먼저** 있어야 한다: §6.4가
"게이트 없이 음성을 켜지 않는다"고 한 것과 같은 논리로, 게이트 없이 도구를 켜지
않는다.

### 8.3 평가 3층

성공 기준을 감상평으로 두면 튜닝을 눈 감고 하게 된다. 한 층만 압축 가능하다.

| 층 | 방법 | 압축 |
|---|---|---|
| **회상 골든셋** | "3주 전에 말한 X를 물으면 정확히 인용하는가" 50문항. 기억 변경마다 회귀 검사 | **가능** (자동) |
| **선제성 1탭 라벨** | 발화마다 👍/👎 인라인 버튼(텔레그램은 공짜). 주간 정밀도 추적. 이 라벨이 튜닝 데이터이자 페르소나 진화의 근거 | 불가 |
| **페르소나 diff 일지** | 주간 스냅샷 + 규칙별 생성 근거. "배운 것" 열람 UI와 같은 산출물이라 사실상 공짜. 여기에 "이번 주 대화 N회/N시간" 한 줄 포함 | 불가 |

## 10. PC 컨트롤 (M1c) — 도구 사용

**정의상 필요한 것.** §1은 Daemon을 "PC에 상주하는" 동반자로 정의하는데, M1b까지의
Daemon은 자기가 사는 기계를 열어볼 수도 없었다. 이건 기능 부족이 아니라 정의 미달이다.

### 10.1 벤치마킹 — Hermes / OpenClaw

| | Hermes Agent | OpenClaw | Daemon |
|---|---|---|---|
| 도구 수 | ~81개, 25 toolset, `tools/registry.py` 자기등록 | ~26개 (`exec`/`process`/`read`/`write`/`browser`/`screen`) | **내장 7개 + MCP.** 유저 1명, 기계 1대 — 81개는 우리가 채울 플랫폼 표면이 아니다 |
| 필터 | toolset 플래그 + 크레덴셜 + 플랫폼 | `tools.allow`/`tools.deny`, **"정책은 모델 호출 전에 적용"** | 비슷함. owner 턴이 아니면 스키마를 아예 안 보내고, 개별 호출은 실행 직전에 다시 판정 |
| exec 안전장치 | **문서상 없음** — `terminal`이 임의 셸 실행 | `tools.exec.mode` = `deny`/`allowlist`/`ask`/`auto`/`full`, 승인 시 **cwd+argv+실행파일 경로 바인딩**, 승인 후 파일 변경되면 거부, allowlist 모드에서 체이닝·리다이렉션 거부, SQLite 영속화 | **거의 그대로 이식** (§10.2). `auto`만 버렸다 — 리뷰어 모델을 쓰는데, 게이트를 열지 물어보는 모델은 게이트가 아니다 |
| 승인 UX | — | 게이트웨이가 `exec.approval.requested` 브로드캐스트, UI 없으면 `askFallback: deny` | 채널로 짧은 코드 — 이미 있는 페어링 플로우와 같은 모양 |
| MCP | — | `mcp` CLI, 서버를 config로 | MCP 클라이언트. 툴은 네임스페이스 + **같은 정책 아래** |

### 10.2 둘 다 풀 필요가 없고 우리만 풀어야 하는 문제

Daemon의 수신 메시지는 **남의 말을 실어올 수 있다.** `authored_by_sender=False`
(전달된 메시지, 인라인봇 결과)면 `origin='untrusted'`로 기록되고, 회상은 *과거에
전달된 무엇이든* 포함해 임의의 옛 텍스트를 매 턴 프롬프트에 넣는다(§4.3).
지금까지 이 경로의 최악은 "모델이 헛소리를 한다"였지만, 도구가 붙으면
**"모델이 셸을 실행한다"**가 된다.

> **오리진 게이트: 턴의 origin이 `owner`가 아니면 어떤 도구도 실행되지 않는다.**
> 모든 모드에서, `full` 포함, 끌 수 있는 설정은 없다.

`messages.origin`이 애초에 위조 불가능한 컬럼인 이유가 정확히 이것이고(§4.2),
`decide()`의 **첫 번째** 검사다. §6.4가 "게이트 없이 음성을 켜지 않는다"고 한 것과
같은 비대칭이다 — 텍스트 오답은 무시하면 되지만 실행된 명령은 되돌릴 수 없다.

### 10.3 셸이 없다

`run_command`는 argv 벡터를 exec한다. `sh`를 띄우지 않는다. 그래서 인젝션 계열이
통째로 사라지고, 대신 파이프를 잃는다(`ls | grep x` 불가). `full` 모드도 이걸 바꾸지
않는다 — `full`은 "묻지 말라"이고 "셸을 달라"가 아니다.

같은 원칙의 두 번째 적용: `notify`의 AppleScript는 **상수**이고 값은 `on run argv`로
넘긴다. `-e 'display notification "TEXT"'`로 조립하면 제목에 인용부호 하나로 임의
AppleScript가 실행된다.

### 10.4 승인은 비동기여야 한다

대화 루프는 단일 스레드이고 **메시지를 읽는 주체 자신**이다(`loop.py:run()`).
승인을 기다리며 턴을 블로킹하면 유저가 승인 코드를 보낼 수 없다 — 아무도 안 듣고
있으므로. 그래서 승인은 `tool_approvals` 행 + 5분 TTL + 1회용 코드로 남기고 턴을
끝내며, `/approve CODE`는 나중에 **평범한 수신 메시지로** 도착해 모델 앞에서
가로채인다. 페어링과 같은 모양이고, 코드는 단일 UPDATE로 소비되므로 재시작 후
재전달돼도 두 번 실행되지 않는다.

### 10.5 브라우저 — 유저가 보고 있는 것을 같이 본다

**왜 도구를 더 늘리면서 이건 넣었나.** §10.1의 결론은 "도구 개수는 차별점이 아니다"인데,
브라우저 읽기는 개수가 아니라 **재료**다. 유저가 지금 무엇을 보고 있는지는 대화에서
나오지 않고 §6.1 게이트의 "포그라운드 앱"보다 해상도가 압도적으로 높다("Chrome"이 아니라
"40분째 이 문서"). 즉 비서 기능이 아니라 **presence 신호**로 들어온다.

도구 3개, `DAEMON_BROWSER_ENABLED`로 따로 켠다. 도구를 켠 것과 **로그인된 세션을 읽게
하는 것은 다른 결정**이므로 스위치도 따로다(`DAEMON_VOICE_ENABLED`와 같은 논리).

| 도구 | 필요한 것 | 하는 일 |
|---|---|---|
| `fetch_page` | 없음 | 공개 URL → 텍스트. 브라우저·로그인 불필요 |
| `list_tabs` | 없음 | 열려 있는 탭의 제목·URL |
| `read_page` | Chrome 설정 1회 | 보고 있는 페이지의 본문 |

**클릭·입력·이동은 일부러 없다.** 그건 Playwright MCP 서버의 일이고, 거기서는 `guarded`로
유저가 명시적으로 켠 뒤에 쓴다.

#### 10.5.1 격리 — 이 파일에서 가장 위험한 것들이다

바꾸는 게 없어서 위험한 게 아니라, **무엇을 어디서 읽는지** 때문에 위험하다.

1. **JS는 상수다.** `execute_javascript(code)` 같은 도구는 없고 앞으로도 없다. 모델이
   코드를 공급할 수 있으면 그 코드는 **로그인된 세션에서** 돈다 — 쿠키를 읽고, 버튼을
   누르고, 유저 이름으로 글을 쓸 수 있다. 스크립트는 `innerText`만 읽는 고정 문자열이고
   AppleScript에 `argv`로 넘어간다(`notify`와 같은 패턴).
2. **페이지를 변형하지 않는다.** 텍스트를 깨끗하게 만들려고 노드를 지우면 **유저가 보고
   있는 화면을 편집**하는 것이다. `innerText`는 렌더링되지 않는 것을 이미 제외한다.
3. **`fetch_page`는 사설망에 못 간다.** 리다이렉트 **매 홉**을 해석해서 검사한다. 우리
   자신의 control plane이 loopback에 있고, MCP 서버도 그럴 수 있고, `169.254.169.254`는
   클라우드 메타데이터다. 이 검사가 없는 fetch 도구는 그 셋을 다 읽는 경로다.
4. **페이지 텍스트는 울타리에 넣는다.** 시스템에서 가장 공격자 통제적인 입력이라, §4.3
   회상과 같은 nonce 구분자로 감싸고 "읽을 자료이지 지시가 아니다"를 명시한다. 본문에서
   울타리 모양 문자열은 먼저 제거한다.
5. **exfiltration은 가시성으로 막는다.** 모델이 URL을 고르는 outbound 요청은 유출
   채널이다. 승인 코드로는 안 막힌다 — 유저가 안 보고 승인하니까. 대신 `🔧 fetch <url>`이
   **그 턴의 답변 맨 앞에** 나온다.

#### 10.5.2 실행해보고 나서야 알게 된 것 세 개

단위 테스트로는 셋 다 안 보였다. CONTRACTS의 "테스트 통과 ≠ 동작"이 정확히 이것이다.

1. **AppleScript는 앱 용어를 컴파일 시점에 해석한다.** `tell application (item 1 of argv)`
   안에서는 `tab`·`URL of tab`·`execute … javascript`가 Chrome 어휘가 아니라 **미지의
   식별자**다. `count of windows` 같은 표준 용어는 되기 때문에 실패가 자의적으로 보인다.
   해결: `using terms from application "Google Chrome"` — 리터럴이 컴파일러에 사전을 주고
   `tell` 대상은 런타임 값으로 남는다. 그래서 앱 이름은 여전히 데이터다.
2. **`tab`은 AppleScript 상수이면서 Chrome 클래스명이다.** tell 블록 안에서는 후자로
   해석돼 컴파일이 깨진다. `character id 9`를 쓴다.
3. **없는 앱을 `tell`하면 실패하지 않는다.** macOS가 *"응용 프로그램 선택"* 대화상자를
   유저 화면에 띄우고 블로킹한다. 실측: `DAEMON_BROWSER_APP` 오타가 20초 뒤 "응답 없음"으로
   나타나고 모달이 유저 작업 위에 남았다. 그래서 `run_command`가 PATH를 확인하는 것과 같은
   방식으로 앱 존재를 먼저 확인한다 — 20초 → **2ms**.

### 10.5.5 기본값 — 도구는 켜져 있고, 안전장치는 스위치가 아니다

처음엔 `DAEMON_TOOLS_ENABLED=false`로 냈다. **뒤집었다.** 근거는 §10 도입부와 같다:
§1이 Daemon을 "PC에 상주하는 동반자"로 정의하는데 기본값이 꺼짐이면 **기본 제품이 여전히
정의 미달**이다. 꺼진 채로 내는 건 신중함이 아니라 정의를 못 지킨 것을 신중함이라 부르는
것이다.

안전한 이유는 이 스위치가 아니라 게이트다:

| | 기본값 | 왜 |
|---|---|---|
| `DAEMON_TOOLS_ENABLED` | **true** | 정의상 필요 |
| `DAEMON_TOOLS_MODE` | `ask` | 기계를 바꾸는 것은 1회용 코드 없이 안 돈다 |
| `DAEMON_TOOLS_ALLOWLIST` | 비어 있음 | 묻지 않고 도는 명령이 **하나도** 없다 |
| 오리진 게이트 | 끌 수 없음 | 유저 자신의 말이 아닌 턴은 도구에 도달하지 못한다 |
| `DAEMON_BROWSER_ENABLED` | **false** | 로그인된 세션을 읽는다 — 별개의 결정 |
| `DAEMON_MCP_ENABLED` | **false** | 남의 서브프로세스를 띄운다 |

즉 기본 설치에서 **묻지 않고 되는 것은 읽기뿐**이다(`read_file`·`list_dir`·`system_state`
·`notify`). 쓰기·실행·열기는 매번 코드를 요구한다.

**대신 조용하면 안 된다.** 처음에는 기본값에 맡기고 `daemon doctor` 한 줄로만 보고하려
했는데 — 아무도 묻지 않은 능력이 어디에도 안 적히는 것이 CLAUDE.md가 경고하는 바로 그
조용한 상태다. 그래서 `daemon setup`이 **1/5단계로 가장 먼저** 묻고, 답을 기본값에 기대지
않고 `DAEMON_TOOLS_ENABLED`로 명시해 파일에 쓴다. 이 마법사에서 "어떻게 동작하는가"가
아니라 "무엇을 해도 되는가"를 묻는 유일한 질문이므로 별도 단계다.

`daemon doctor`도 같은 상태를 한 줄로 보고한다 —
`tools: on mode=ask roots=~ runs-without-asking=nothing`. `mode=full`은 detail이 아니라
**실패한 체크**로 보고한다.

**비용은 프롬프트뿐이다.** 켜져 있으면 TOOL_CONTRACT 684자(≈170토큰) + 도구 스키마
(내장 7개 ≈620토큰)가 매 턴 들어간다. 실측: 도구를 켜고 모델이 도구를 쓰지 않은 턴은
모델 호출 수·답변·`messages` 행·벡터 수·마크다운 로그가 **끈 것과 완전히 동일하다**.
기억·회상·선제성은 도구 레이어를 임포트조차 하지 않는다.

### 10.6 QA에서 실제로 나온 결함들

**단위 테스트 999개가 전부 초록인 상태에서 적대적으로 찔러보니 6개가 나왔다.** 기록해두는
이유는 §8.2의 교훈과 같다 — 통과하는 테스트는 "안 깨진다"를 증명하지 "맞다"를 증명하지 않는다.

| # | 결함 | 어떻게 찾았나 | 심각도 |
|---|---|---|---|
| 1 | **allowlist basename 우회.** `allowlist=["ls"]`가 `/tmp/아무데나/ls`를 **승인 없이** 실행 | 직접 스크립트를 놓고 실행시켜 봄 → `PWNED` 출력 | **높음** — allowlist 모드를 통째로 우회. `write_file`과 조합하면 정책 밖으로 나감 |
| 2 | **`run_command` 출력 무제한.** stdout 200MB → RSS **+651MB** | RSS 측정 프로브 | 높음 — `cat` 한 번으로 프로세스가 죽음 |
| 3 | **`fetch_page` 응답 무제한.** `FETCH_MAX_BYTES`가 *보관량*만 제한, 수신량은 무제한 | 같은 프로브 | 중간 |
| 4 | **MCP `_register`가 try 밖.** 서버 하나가 `list_tools`에서 멈추면 **나머지 서버의 툴까지** 다 잃음 | 커버리지가 `start()` 미도달을 지적 → 테스트 작성 | 중간 |
| 5 | **`notify-send`에 `--` 없음.** 제목 `--help`가 옵션으로 파싱 | argv 프로브 | 낮음 |
| 6 | **`PathScope`가 `ValueError`를 안 잡음.** 널바이트 루트 하나가 **정상 루트까지** 다 날림 | 커버리지 → 테스트 작성 | 낮음 |

전부 고치고 회귀 테스트를 붙였다. 1번은 OpenClaw가 "pinned executable path"를 하는
이유를 뒤늦게 이해한 셈이다.

**커버리지로 찾은 것이 2개(4·6번)라는 게 요점이다.** 두 개 다 "테스트가 도달조차 안 한
분기"였고, 도달하게 만들자마자 터졌다. `daemon/tools/`는 97.6%이고 `daemon/tools/policy.py`·`daemon/tools/runner.py`는
100%다 — 남은 25줄은 실제 MCP SDK 연결 경로로, 실제 서버를 띄워 수동 검증했다.

**라이브 QA에서 배운 것 하나:** 실제 모델을 쓰면 "어떤 도구를 골랐는지"로 단정할 수 없다.
날짜를 물었을 때 모델은 `run_command date` 대신 `system_state`를 골랐고(설명이 그러라고
시키므로 옳은 선택), 전달된 메시지 테스트에서는 도구를 아예 안 불러서 게이트가 **시험되지
않은 채로 통과**했다. 그래서 오리진 게이트 같은 불변식은 도구 호출을 강제하는
E2E(`tests/test_e2e.py`)에서 검증하고, 라이브는 감사 기록으로만 판정한다.

  `daemon/proactivity/presence.py`에 **위임한다** — 두 구현을 두는 것은 틀린 판독값을
  맞는 것 옆에 두는 것이었다.
- `list_tabs`는 아직 게이트가 쓰지 않는다. 포그라운드 앱보다 해상도가 높은 신호이므로
  §6.1의 후보·게이트에 넣을 값이 있다.
- **도구 결과가 기억으로 가지 않는다.** `read_page`가 "발표는 목요일"을 읽어도 그 턴의
  컨텍스트에만 들어가고 `tool_calls`에는 감사 기록으로만 남는다. 즉 지금 Daemon은 유저
  기계를 읽을 수 있지만 **그걸로 유저를 알게 되지는 않는다.** M2의 관찰 수집이 대화만
  보지 말고 도구 결과도 봐야 한다 — 이게 §10을 §5·§6에 연결하는 다리이고, 없으면 PC
  컨트롤은 §6.2가 경고한 "유능한 비서"로 남는다.
- **선제 턴의 도구 사용은 지금 막혀 있다.** 오리진 게이트가 `owner`만 통과시키므로 선제
  턴(`origin='agent'`)은 모든 도구가 거부된다. 우연히 안전한 쪽이 기본값이 됐다. 뚫으려면
  명시적 결정이 필요하고, 제안은 "선제 턴은 읽기 전용 도구만" 한 줄이다. M3 설계 시 결정.
